# EAST Creative Report 코멘트 초안

생성기가 만든 pptx 의 빈 코멘트 박스에 초안을 넣어 돌려준다. 마케터가 검토·수정한 뒤 리뷰어에게 넘긴다.

## 지켜야 할 원칙
1. **숫자는 슬라이드 KPI 문자열 그대로만.** 차이·증감·평균을 계산하지 않는다. 소재 이미지 속 카피 숫자(예: 40% OFF, RM39)는 인용 가능하되 drafts.json 의 `allowed_numbers` 에 적는다.
2. **이미지에서 보이는 것만 사실로 쓴다.** 이미지에서 확인되지 않은 추측(원인 가설)은 본문에 넣지 말고 노트에 "근거 약함"으로 남긴다.
3. **전월·연속 표현은 소재이력에서 찾은 행이 있을 때만.** 찾은 행(월·구분·캠페인)을 노트에 그대로 적는다.
   - 같은 소재로 보는 기준: 소재명이 정확히 같은 행. 이름이 비슷하기만 하면 "유사 소재"로만 쓴다.
   - "N개월 연속"은 끊김 없이 이어진 **[확인됨] 행 수 + 이번 달**로 센다. 중간에 [추정] 행이 끼면 숫자 없이 "전월에 이어 연속 저조군"으로 쓰고 노트에 [추정] 행을 적는다.
   - 같은 소재명이 다른 캠페인 라벨(예: 전월 Video Contents → 이번 UA)에 있었으면 "전월 ○○ 캠페인에서도 우수"처럼 캠페인을 밝힌다. 연속 개월 수로 합치지 않는다.
   - PR 소재명은 달마다 재사용된다. 이미지의 행사 날짜·구성이 전월과 다르면 같은 소재로 보지 말고 "전월과 같은 형식(예: $5 단일가 Flash Deal)"처럼 **형식의 연속성**으로 쓴다.
4. 참고 파일 우선순위: **판정결과 > 국가 성과패턴 > 공통 성과패턴.** 패턴과 반대 결과면 단정하지 말고 "~가능성", 노트에 "기존 패턴과 다름".
5. 슬라이드 제목·KPI·소재명·이미지는 건드리지 않는다. 코멘트 박스와 노트 칸만 바꾼다.
6. 광고주 데이터다. 결과물은 사용자에게만 돌려주고 다른 곳에 올리지 않는다.

## 순서

### 1. 입력 확인
- 사용자가 올린 pptx 경로를 확인한다. 리포트 월(예: 26년 10월)과 데이터 기간은 표지에서 읽고, 없으면 묻는다. 전월 = 그 앞 달.
- 운영 메모(신규 SKU 출시, 프로모션 일정, 예산 변경 등)가 있으면 받는다. 없으면 진행.

### 2. 슬라이드 추출
```bash
python <스킬폴더>/scripts/extract_slides.py "<입력.pptx>" "<작업폴더>"
```
`<스킬폴더>` 는 이 SKILL.md 가 있는 폴더의 절대 경로다.
`작업폴더/slides.json`(슬라이드별 제목·슬롯 라벨·우수/저조·소재명·영상 여부·KPI·이미지 경로), `작업폴더/cover.json`(리포트명·데이터 기간), `작업폴더/images/` 가 생긴다.
- 기간을 못 찾았으면 사용자에게 묻는다.
- 이미 코멘트가 있는 슬라이드는 `existing_comment` 에 들어 있으니, 덮어쓸지 사용자에게 확인한다.
- `media` 가 영상인 슬롯은 썸네일 1프레임만 있다. 영상 길이·초반 구성은 판단하지 말고, 썸네일에서 보이는 것만 쓴다.

### 2-1. 데이터 이상 점검 (본문에 쓰지 말고 노트 + 사용자 보고)
- 이미지 속 행사 날짜가 데이터 기간 밖이거나 월이 다름 (예: 9월 행사 이미지가 10월 슬롯에) → "이미지 매칭 확인 필요"
- 슬롯 라벨(캠페인)과 소재명 속 캠페인 토큰이 다름 (예: 라벨 BeautyBonanza, 소재명 HYC-Day) → "라벨·소재명 불일치"
- 소재명 토큰과 이미지 내용이 다름 (예: Product_Discount 인데 할인 표기 없음) → 이미지 기준으로 쓰고 노트에 기록
- 저조 슬롯의 KPI 가 같은 슬라이드 우수 슬롯보다 좋아 보임 (KPI 문자열을 나란히 비교만, 계산 없이) → "우수·저조 분류 확인 필요". 본문에서는 "상대 평가 기준 저조"로만 쓴다.

### 3. 참고 파일 읽기
작성형식 → 리뷰어규칙 → 판정결과 → 공통 → 해당 국가 성과패턴 → 해당 국가 소재이력(이번 소재명 검색) 순서.

### 4. 슬라이드마다 초안 작성
1. **이미지를 하나씩 직접 본다.** 소재마다 아래 체크리스트를 노트용으로 적는다.
   - 첫 화면 핵심 메시지 1개 / 판매가·할인율 노출 여부와 문구 / 혜택 종류·개수(쿠폰 몇 종, 증정, FlashDeal 시간대) / 제품 수·세트 구성 / 모델·인물·BnA·리뷰 유무 / 배치(중앙·좌우 분산·박스·캘린더) / 텍스트 양 / 배경 대비
2. 우수 소재끼리, 저조 소재끼리 공통점을 찾고 우수 vs 저조 차이를 찾는다 (같은 캠페인 라벨끼리 우선 비교).
3. 소재이력에서 전월(또는 그 이전) 기록을 찾는다 → "전월에 이어", "N개월 연속", "전월과 달리".
4. 성과패턴·판정결과에서 맞는 패턴을 고르고 반례를 확인한다 (R5).
5. 작성형식대로 쓴다.
   - 3줄형(MY·SG 기본): 공통 패턴 / 캠페인별 특이점·전월 연속성 / 대비 해석 + `▶` 제언
   - 라벨형(ID 상시·PR, SG 우수<>저조 통합): `라벨 : 설명` 줄을 **라벨당 1줄** + `▶ 따라서 … 필요`. 같은 라벨 슬롯이 여럿이면 한 줄에 함께 쓴다. 라벨이 2개뿐이면 본문 2줄도 괜찮다. PR 라벨은 월을 붙인다 (`Payday-Oct :`, R9). 월은 이미지 속 행사 날짜로 판단하고, 안 보이면 리포트 월
   - 한 슬라이드 안에서 '우수 vs 저조' 대비 문장은 꼭 1개 이상 (R4)
   - 개조식 명사형 종결, 한 줄 110자 이내, 같은 어미 3번 반복 금지, 수치는 1~2개
6. 콜아웃 후보 0~4개 (6~12자 명사구, 이미지에서 바로 보이는 이유에만).

### 5. drafts.json 저장
```json
[{"slide_no": 4,
  "body": ["줄1", "줄2", "줄3"],
  "arrow": "▶ … 제언",
  "callouts": [{"slot": 3, "text": "리뷰 설명 비중 높음"}],
  "allowed_numbers": ["40% (Payday 바우처 이미지 카피)"],
  "notes": ["근거: P-MY-01, 판정 MY J-01", "소재이력: … 26-08 우수, 26-09 우수 → 3개월 연속",
            "이미지 판독: 슬롯1 할인율·판매가 전면 / 슬롯3 리뷰 문구가 화면 절반",
            "플래그: 근거 약함 — …"]}]
```

### 6. 자동 점검 → 고치기
```bash
python <스킬폴더>/scripts/check_drafts.py "<작업폴더>"
```
'~다.' 종결, 단정 표현, KPI 에 없는 숫자, 줄 수·길이, ▶ 어미, 어미 반복을 본다. 나온 항목을 고치고 통과할 때까지 다시 돌린다. 그다음 리뷰어규칙의 "초안 점검 순서" 1~5를 직접 확인한다.

### 7. pptx 에 넣기
```bash
python <스킬폴더>/scripts/insert_comments.py "<입력.pptx>" "<작업폴더>" "<출력.pptx>"
```
코멘트 박스에 본문과 ▶ 줄을 run 단위로 넣고(서식 유지), 근거·콜아웃 후보·플래그는 슬라이드 노트 칸에 넣는다. 최종 공유본에서 노트를 지울 때는 `--no-notes`.

### 8. 사용자에게 돌려주기
- 출력 pptx 파일
- 슬라이드별 한 줄 요약: 핵심 진단 + 플래그(근거 약함 / 기존 패턴과 다름 / 이미지 없음 / 우수·저조 분류 확인 필요)
- 마케터가 꼭 확인할 것 3개 이내

## 아직 못 하는 것 (알려진 한계)
- R3(전월 코멘트와 표현 겹침 피하기): 전월 FN 코멘트 원문 파일이 아직 없다. 생기면 참고 파일에 추가하고 이 단계에서 비교한다.
- 영상 소재는 썸네일 1장만 본다.

## 하지 않는 것
- 슬라이드 순서·소재 선택 변경, KPI 수정
- 참고 파일 수정 (월간 학습 단계에서 지윤님 판정 후 따로 반영)
- 이미지 위 빨간 박스 그리기 (위치는 마케터가 정함, 문구 후보만 노트에)
