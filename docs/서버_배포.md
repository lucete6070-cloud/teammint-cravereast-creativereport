# 서버 배포 (Google Cloud Run 기준)

보조는 주소만 열면 되는 방식입니다. 로그인은 팀민트 구글 계정(@team-mint.io)만 되고, 구글 시트 주소를 붙여넣으면 서버가 국가 탭을 읽어 pptx 를 만듭니다.
이 문서는 **서버를 올려 줄 사람(Google Cloud 권한이 있는 팀 인프라 담당 또는 지윤님)** 이 따라 하는 순서입니다. 명령어는 복사해서 쓰면 됩니다. [미확인] 표시는 실제 계정에서 처음 해 보며 확인이 필요한 부분입니다.

## 0. 동작 방식 (한 줄 요약)
- 서버 한 대(Cloud Run)가 웹 화면 + 생성 프로그램을 돌립니다. 데이터는 **작업하는 동안만** 서버에 있고, 로그아웃하거나 3시간이 지나면 자동 삭제됩니다.
- 구글 로그인: 로그인한 본인 권한으로 시트를 읽습니다(읽기 전용). 월마다 시트가 새로 생겨도 서버에 따로 공유할 필요가 없습니다.
- Meta 토큰·광고계정은 서버 설정에 한 번만 넣습니다. 보조는 토큰을 보지 못합니다.

## 1. 준비물
| 필요한 것 | 설명 |
|---|---|
| Google Cloud 프로젝트 1개 | 결제 계정 연결 필요. 사용량이 적어 월 몇 달러 이하일 가능성이 큼 [미확인] |
| 사용할 API 켜기 | Cloud Run, Cloud Build, Artifact Registry, Secret Manager, Google Sheets API |
| 권한 | 위 프로젝트에서 Cloud Run 배포, OAuth 클라이언트 생성, Secret 만들기가 가능한 계정 |
| Meta 장기 토큰 + 국가별 광고계정 ID | 지윤님이 가진 값 (토큰은 채팅·문서에 쓰지 말고 아래 2단계에서 바로 비밀 저장소에 넣기) |

## 2. 비밀 값 저장 (Secret Manager)
```
echo -n "여기에Meta토큰" | gcloud secrets create meta-token --data-file=-
echo -n "여기에구글클라이언트시크릿" | gcloud secrets create google-client-secret --data-file=-
```
(구글 클라이언트 시크릿은 아래 3단계 후에 만들 수 있으므로 3단계 다음에 실행하세요.)

## 3. 구글 로그인 설정 (OAuth)
1. 콘솔 → API 및 서비스 → **OAuth 동의 화면**: 사용자 유형 **"내부(Internal)"** 선택 → 앱 이름 "Creative Report", 지원 이메일 입력.
   - 내부로 하면 팀민트 계정만 쓸 수 있고, 구글의 앱 검수 없이 시트 읽기 권한을 쓸 수 있습니다 [미확인: 조직 설정에 따라 다를 수 있음].
2. **범위(Scopes)** 추가: `openid`, `email`, `https://www.googleapis.com/auth/spreadsheets.readonly`
3. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기**: 유형 "웹 애플리케이션".
   - **승인된 리디렉션 URI**: `https://서비스주소/oauth/callback` — 서비스 주소는 5단계에서 첫 배포 후에 알게 되므로 일단 비워 두고, 5단계 뒤에 추가합니다.
4. 만들어진 **클라이언트 ID / 클라이언트 보안 비밀**을 메모합니다 (비밀은 2단계 명령으로 저장).

## 4. 프로그램 코드 받기
```
git clone https://github.com/lucete6070-cloud/teammint-cravereast-creativereport.git
cd teammint-cravereast-creativereport
```

## 5. 배포 (처음 한 번은 두 번 배포)
**① 첫 배포** — 서비스 주소를 알아내기 위한 배포입니다.
```
gcloud run deploy creative-report --source . --region asia-northeast3 --allow-unauthenticated ^
  --max-instances 1 --session-affinity --no-cpu-throttling --memory 1Gi --cpu 2 --timeout 900 ^
  --set-env-vars APP_MODE=server,ALLOWED_DOMAIN=team-mint.io,GOOGLE_CLIENT_ID=클라이언트ID,PUBLIC_URL=https://임시값.run.app,META_AD_ACCOUNT_ID_MY=MY계정ID,META_AD_ACCOUNT_ID_SG=SG계정ID,META_TOKEN_ISSUED=2026-10-15 ^
  --set-secrets META_ACCESS_TOKEN=meta-token:latest,GOOGLE_CLIENT_SECRET=google-client-secret:latest
```
(Windows 가 아니면 줄 끝의 `^` 대신 `\` 를 쓰세요.) 끝나면 `Service URL: https://creative-report-xxxx.run.app` 가 출력됩니다.

**② 주소 반영** — 출력된 주소로 두 군데를 고칩니다.
1. 3단계의 OAuth 클라이언트 **승인된 리디렉션 URI** 에 `https://creative-report-xxxx.run.app/oauth/callback` 추가.
2. `PUBLIC_URL` 을 그 주소로 바꿔 다시 배포:
```
gcloud run services update creative-report --region asia-northeast3 --update-env-vars PUBLIC_URL=https://creative-report-xxxx.run.app
```

옵션 설명: `--max-instances 1 --session-affinity` 는 로그인 정보를 서버 메모리에 두기 때문에 한 대로 유지하려는 설정입니다. `--no-cpu-throttling` 은 화면을 닫아도 생성 작업이 끊기지 않게 합니다. 동시에 3명 정도까지 쓰는 규모를 가정했고, 더 늘면 메모리·CPU 를 키우세요.
`--allow-unauthenticated` 는 주소 접속 자체는 막지 않지만, 프로그램이 구글 로그인(@team-mint.io)이 없으면 어떤 데이터도 보여 주지 않습니다. 더 강한 제한이 필요하면 Cloud Run 의 IAP 를 추가로 켤 수 있습니다.

## 6. 확인 순서
1. 주소를 열면 구글 로그인 창 → 팀민트 계정으로 로그인 → 화면이 열리는지
2. "연결 확인하기"에서 MY·SG 광고계정 연결이 초록색인지
3. 시트 주소를 붙여넣고 [시트에서 가져오기] → 국가 탭 4개가 보이는지
4. 담당 국가를 체크하고 [생성하기] → pptx 가 내려받아지는지
5. 팀민트 밖 계정(예: gmail)으로 로그인하면 거부되는지

## 7. 운영
- **토큰 갱신(약 60일마다)**: `echo -n "새토큰" | gcloud secrets versions add meta-token --data-file=-` 후 `gcloud run services update creative-report --region asia-northeast3 --update-env-vars META_TOKEN_ISSUED=오늘날짜` (새 버전 반영을 위해 재배포됨).
- **프로그램 업데이트**: 코드를 `git pull` 한 뒤 5-①의 `gcloud run deploy ...` 를 다시 실행 (옵션은 이미 저장돼 있어 `gcloud run deploy creative-report --source . --region asia-northeast3` 만으로 됩니다).
- **로그 확인**: 콘솔 → Cloud Run → creative-report → 로그. 토큰은 로그에 남지 않습니다.
- **데이터**: 올린 CSV·받은 이미지·결과는 서버 임시 폴더에만 있고, 로그아웃 또는 3시간 후 삭제됩니다. 서버를 다시 시작해도 사라집니다.

## 8. 제한과 알아둘 점
- 서버가 재시작되면 로그인과 진행 중 작업이 끊깁니다. 다시 로그인해서 시트를 가져오면 됩니다.
- 동시 사용자가 많아지면 서버를 키우거나, 로그인 정보 저장을 외부 저장소로 옮기는 개선이 필요합니다.
- 이 배포 절차는 이 개발 환경에서 직접 실행해 보지 못했습니다(로컬 시험은 가짜 구글·Meta 서버로 통과). 실제 계정에서 5~6단계를 확인해 주세요 [미확인].
